Active Learning API

The Annotation Hub's feed, its labels, and its retraining all go through the backend's active-learning endpoints under /api/pam-al. This page follows them in the order the Hub uses them. For the concepts, see Active Learning.

Before the first model

EndpointUsed for
GET /api/pam-al/checkpoints?dataset_id=Whether the dataset already has an active checkpoint. Without one, the Generate Feed dialog offers a cold start or bootstrap mode.
GET /api/pam-al/datasets/{dataset_id}/training-path-defaultsDefault metadata and label-config paths for the cold-start fields.
POST /api/pam-al/train-from-scratchStarts a cold-start training job from ground-truth metadata. Administrators and team owners only.

Requesting the feed

POST /api/pam-al/inference/get-or-create
{
  "dataset_id": 1,
  "snippet_set_id": 1,
  "model_family_name": "cold_start_base",
  "sample_suggestion": true,
  "suggestion_strategy": "uncertainty",
  "k": 20
}
FieldNotes
dataset_idTarget dataset.
snippet_set_idThe dataset's default snippet set.
model_family_nameThe model family entered in the Generate Feed dialog.
sample_suggestiontrue when "Return only Top-K suggestions" is on, so that a ranked subset is returned; false returns all predictions for the snippet set.
suggestion_strategyThe ranking; the user-study Hub sends uncertainty.
kTop-K, 1 to 500 in the Generate Feed dialog.

If predictions for the dataset's active checkpoint are already stored, they are returned directly: the model family, the checkpoint used, the number of predictions and of returned rows, the strategy, and the rows. Each row holds the snippet and recording IDs, the predicted labels and probabilities, and the uncertainty, diversity, density, and composite scores; the Hub uses the predictions for ranking and scores but never shows the predicted labels. Otherwise an inference job is started and the response identifies it, so that the Hub can poll until the predictions are ready. When the dataset has no checkpoint yet, random snippet suggestions are returned immediately — bootstrap mode.

Labels as feedback

POST /api/pam-al/feedback
{ "dataset_id": 1, "model_family_name": "cold_start_base",
  "snippet_id": 42, "action": "MODIFY", "labels": ["Turdus merula"] }

The Hub sends the annotator's selected labels with the action MODIFY shortly after the selection changes. The schema also accepts ACCEPT and REJECT, which refer to the model's predicted labels; the user-study interface never sends them. The caller needs access to the dataset.

Retraining

EndpointUsed for
GET /api/pam-al/feedback-countThe feedback count for the dataset and model family, against the retrain threshold.
GET /api/pam-al/retrain/jobs/{job_id}Polls a retrain or training job. The feedback response names the job when a submission starts an automatic retrain; when it finishes, the Hub requests new predictions.

Labels and species for the workspace

EndpointUsed for
GET /api/pam-al/labeled-snippetsSnippets that already have a label, marked in the projection.
GET /api/pam-al/snippet-labelsLabels already stored for each snippet, shown on the feed cards. Requires dataset access.
GET /api/pam-al/checkpoints/{checkpoint_id}/speciesThe species the active checkpoint was trained on, for the quick-label list.
GET /api/pam-al/species-defaultThe default species list, used for the quick-label list when no checkpoint species are available.
Other active-learning endpoints. The backend has further /api/pam-al endpoints — registering and activating checkpoints, listing all checkpoints and retrain jobs, manual retraining, and deleting stored labels — that the user-study interface does not call. They are listed separately in the REST API reference.
