Annotation Hub

The Annotation Hub is where annotation happens. In the user-study version it runs one active-learning workflow per dataset, and the selected study phase decides which parts of the workspace are shown.

Opening the hub

/annotate?dataset_id=1

The hub requires a signed-in user. If no dataset is specified, it restores the dataset you last used, which the browser remembers per user, or selects the only dataset when exactly one is available. The older routes /v2AnnotationHub and /active-learning redirect to /annotate.

The toolbar holds a dataset selector and a phase selector. The phase is taken from the phase URL parameter, from the browser's stored choice, or from the deployment's default (VITE_STUDY_PHASE, otherwise P1). A deployment can lock the phase, in which case the URL and the stored choice are ignored; see Environment Setup.

Study phases

Phase What the workspace shows
Phase 1 The feed only, without projection or sidebar.
Phase 2 The feed and the projection of the whole dataset.
Phase 3 Adds the sidebar with the status filter (including a species selection for labelled snippets) and the location and date and time filters.
Phase 4 Adds the model-derived score histograms, and sorting by model scores and by date and time.
Phase 5 As phase 4; points in the projection can also be clicked to select a snippet.

The phase selector lists the phases a deployment allows (VITE_STUDY_PHASE_ALLOWED, otherwise all five).

Guided study flow

When the guided study flow is on (VITE_STUDY_FLOW_ENABLED, on by default when the phase is locked), each phase goes through these steps:

  1. Instructions. A dialog titled "Welcome to Phase N" explains what is new in that phase — the feed in phase 1, the feature projection in phase 2, the metadata filters in phase 3, the model-derived filters and feed sorting in phase 4, and clickable projection points in phase 5 — and waits for the participant to begin.
  2. Guided tour. Cards highlight the parts of the screen that are new: the clip, choosing a label, moving to the next sample, and a tip in phase 1; the projection and zooming in phase 2; the metadata filters in phase 3; the model-derived scores, each with an animated explainer, and sorting in phase 4; and clicking projection points in phase 5. A card already shown in an earlier phase is not repeated. Every phase ends with a task card that lists the target species, which are defined in the frontend code.
  3. Annotating. A message confirms that the annotation session has started, and the participant works in the Hub.
No countdown in this version. The instructions text mentions 15 minutes per phase (40 in phase 5), but the flow's countdown is switched off in the user-study frontend (TIMER_ENABLED = false in StudyFlowProvider.tsx), and no timer is displayed. Phases therefore do not advance on their own, and the completion screen that would follow the last phase is not reached. Participants move between phases with the phase selector, which restarts the chosen phase at its instructions.

The flow's progress — the step each phase has reached and the tour cards already seen — is stored in the browser, so reloading the page resumes where the participant left off. Opening /annotate?study_reset=1 clears that stored progress and returns to the first allowed phase.

The workspace

The workspace is a resizable split view:

  • ProjectionView — a two-dimensional view of the dataset's snippets, useful for seeing clusters and where the current snippet sits. Buttons above it switch between PCA (the default), UMAP, and t-SNE.
  • PredictionFeed — the scrollable list of snippet cards to review, each with its spectrogram, player, and labels.

The sidebar filters and the model-score thresholds narrow both the projection and the feed; see Filters and Model Scores.

Configuring a feed

Generate Feed (or Edit Feed once a feed exists) opens one configuration dialog:

Situation Options
No model checkpoint yet Model family name, and whether ground-truth metadata is available. With it, a cold start asks for the embedding model, the metadata and label-config paths, the device, and whether to run inference after training. Without it, the session starts in bootstrap mode with random snippets.
All feeds Top-K (1 to 500) and whether to return only the Top-K suggestions.

The dataset needs a ready snippet set; otherwise the dialog warns that embeddings must be generated first.

Reviewing and labelling

Labelling is blind: the model's predicted labels are not shown. On each card you select one or more labels from the quick-label list, or search GBIF for a species, which also pins it to your personal quick labels. Changes are saved automatically after a short pause.

Each labelled snippet is recorded as active-learning feedback and counts toward the auto-retrain threshold. When a retrain finishes, the feed is refreshed with the new model's ranking.

Study logging

When a deployment enables study logging (VITE_STUDY_LOGGING_ENABLED; off by default), the Hub records a timestamped stream of the participant's interactions — for example label selections, audio playback, filter and sort changes, projection-method changes, and study-flow events. A logging session starts when the Hub page opens and ends when it is left. Events are sent to the backend in batches (every VITE_STUDY_LOGGING_FLUSH_SECONDS, 10 by default) and once more when the page is closed. The backend attributes each batch to the signed-in user.

Study Logs viewer

Administrators open the Study Logs card on the Dashboard (/study-logs); other roles are redirected to the Dashboard. The viewer has three levels:

  • Participants — each user with recorded events: sessions, total events, and when they were last seen.
  • Sessions — one participant's sessions: number of events, start time, duration, and the phases visited.
  • Events — one session's event timeline, which can be downloaded as CSV.
Remember. The model ranks snippets but never proposes a label on the card. See Active Learning for how the ranking and retraining work.
