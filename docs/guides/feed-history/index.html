Feed History

Every classic feed you generate is saved as a snapshot. Feed History lets you review those snapshots and reopen a previous configuration instead of rebuilding it from scratch.

What is stored

Generating a feed records the request that produced it — the method, the dataset, and the parameters such as limit and filters. Snapshots are kept per user and per method, and up to five are retained for each method. When a new one is created, the oldest is dropped.

The history endpoint returns these snapshots newest first: 

GET /api/feed/history?method=random&dataset_id=1

Both filters are optional. Filtering by dataset matches against the stored request parameters, so you can narrow the list to the dataset you are working on.

In the interface

The Feed History page lists the stored snapshots. Each entry shows the method, the number of snippets, and the creation time, with an Open button that returns to the annotation workflow for that feed (/annotate?feed_id=).

Why it helps

  • Resume annotation on a batch you were partway through.
  • Reuse a carefully tuned similarity or filter configuration.
  • Compare how a dataset was sampled across sessions.
Note. Feed History covers the classic methods (random, similarity, and filter). Active-learning and validate sessions are configured per model checkpoint rather than stored as classic snapshots.
