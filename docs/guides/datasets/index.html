Datasets

The Datasets page is the entry point for the data you annotate. It lists every dataset you can access and exposes the actions that prepare a dataset for feeds.

Creating a dataset

In the interface, only administrators can create datasets. The creation form collects:

Field Notes
Name Display name of the dataset.
Dataset type PAM for soundscapes, FOCAL_RECORDINGS for the species-model workflow.
Source folder Chosen from the mounted data volume with the folder picker.
Team Assigns the dataset to a team. The API requires it for non-administrators.
Spectrogram range Optional frequency bounds used when rendering spectrograms.

On save, the API creates the dataset and dispatches a background processing task that scans the folder and discovers recordings. The response includes the task identifier used to follow progress.

Dataset readiness

A newly created dataset is not immediately usable. It passes through two gates:

  1. Recordings present — after the scan task completes.
  2. Embeddings present — after an embedding job completes and the dataset's default snippet set is ready.

The dataset card shows these states, and feed generation stays disabled until the dataset is ready for feeds.

Inspecting a dataset

  • Explorer — shows the folder and audio-file structure discovered on disk.
  • Recording locations — the distinct location values available for filter feeds.
  • Quick labels — a short list of commonly used labels; if unset, the page falls back to the species list of the active checkpoint, without saving it.
  • Annotation stats — per-dataset counts across accessible datasets.

Editing and deleting

Administrators and the owning team's owner can update metadata such as the name, description, type, source folder, and spectrogram range, and the dataset's retrain_after_threshold, the number of feedback entries after which active-learning retraining is triggered. Deleting a dataset removes it and its recordings; the action requires the same management permission.
