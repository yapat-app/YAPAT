Datasets

The Datasets page is the entry point for the data you annotate. It lists every dataset you can access, with filters by team and dataset type and sorting by name, age, snippet count, or annotation count, and exposes the actions that prepare a dataset for annotation.

Creating a dataset

The Add Dataset action is shown to administrators and team owners. Its folder picker relies on an administrator-only endpoint, so in practice an administrator registers new datasets. The creation form collects:

Field Notes
Name Display name of the dataset.
Description Optional free text.
Dataset type PAM for soundscapes, FOCAL_RECORDINGS for the species-model workflow.
Source folder Chosen from the mounted data volume with the folder picker.
Team Optional in the form; leaving it empty creates an unassigned dataset. The API requires it for non-administrators.
Max spectrogram frequency Optional upper frequency in kHz used when rendering spectrograms; empty means the full band.

On save, the API creates the dataset and dispatches a background processing task that scans the folder and discovers recordings. The response includes the task identifier used to follow progress.

Dataset readiness

A newly created dataset is not immediately usable. It passes through two gates:

  1. Recordings present — after the scan task completes.
  2. Embeddings present — after an embedding job completes and the dataset's default snippet set is ready.

The dataset card shows these states. Until the dataset is ready for feeds, the Annotation Hub's Generate Feed dialog warns that embeddings must be generated first.

Inspecting a dataset

  • Files — the card's audio-file count opens a searchable, paged list of the dataset's recordings.
  • Metadata — download a CSV template, then upload recording metadata such as location, date, and time; locations can be reviewed and renamed before import. The Annotation Hub's filters use these values.
  • Quick labels — the card shows the first five of the dataset's quick labels; Manage opens the quick-label manager described below.
  • Annotation stats — the card shows the number of audio files, snippets, and annotated snippets.
  • Active Learning — opens the Annotation Hub for the dataset in the current study phase.
  • Export — downloads the dataset's annotations as CSV or JSON, once at least one snippet is annotated; see Import & Export.

The folder scan runs once, when the dataset is created. The interface has no control for scanning a dataset again.

Quick-label manager

Manage on a dataset card opens the dataset's quick-label list. It is available to every signed-in user. The left side lists the current labels, each of which can be removed; the right side adds labels from three sources:

  • GBIF — species search through the backend's taxonomy suggestions.
  • ENVO — environmental terms such as rain or wind, searched through the Ontology Lookup Service.
  • Local — free text, stored with a local: identifier, for labels such as "No biophony".

Save replaces the dataset's stored list. In the Annotation Hub, this list is merged with the model checkpoint's species, the team's most recently frozen label space, and each annotator's personal quick labels, which are the species they pinned from the Hub's GBIF search.

Editing and deleting

On the card, administrators and team owners can change the spectrogram display settings. The user-study interface has no control for renaming, editing, or deleting a dataset.

Focal-recording datasets and WSSED

FOCAL_RECORDINGS datasets are used with the WSSED page (weakly supervised sound event detection). Its Dashboard card is shown to administrators and to users who can access at least one such dataset; the page checks the same access when opened. It trains a model on the separate WSSED GPU server and registers it for active learning:

  1. Select a dataset. The Dataset Explorer on the left lists the datasets and their stored audio. Until one is selected, the training panel stays locked.
  2. Configure training. The training panel on the right chooses the model — BirdNET (the default), CDur, or TALNet — and its settings: pooling method, training epochs (default 50), learning rate, detection threshold, sample rate, and mel bands, plus bag and hop length for CDur and TALNet. For BirdNET, the panel shows whether embeddings and a checkpoint already exist on the GPU server.
  3. Train. Start Training creates a training job on the GPU server. The panel polls its status every five seconds and shows the epoch progress; after a reload, a running job is picked up again. The job ends as completed or failed.
  4. Register for Active Learning. Once training has completed, the centre panel offers Register for Active Learning, which copies the trained model into the active-learning checkpoint store and registers it under a model family.
  5. Open Active Learning. This button leads to the Annotation Hub. It uses the older /active-learning route, which redirects to /annotate without the dataset and model family, so the Hub opens with the dataset you last used.

The backend also has WSSED endpoints for reviewing and retraining on the species model (suggestions, labels, retraining, and a confidence histogram). The user-study interface does not use them; see REST API.

Next step. With recordings in place, the interface lets an administrator generate embeddings; then open the Annotation Hub. The card also shows an older Generate Feed button that is not part of the user-study workflow: the feeds it creates are not shown in the Annotation Hub. Use Generate Feed inside the Annotation Hub instead.
