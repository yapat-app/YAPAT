Deployment

The recommended deployment runs the complete Docker Compose stack. This page covers what each piece does and the operational settings that matter at scale.

Components

Service Role
api FastAPI application. The base Compose file starts one uvicorn process; the override file starts four workers.
celery-worker General queues: embeddings, processing, exports, default.
celery-worker-pam-al Dedicated worker for the pam_al queue; heavy training.
celery-beat Periodic scheduler.
flower Celery monitoring dashboard on port 5555.
db / redis PostgreSQL with pgvector; Redis broker and result backend.

Async processing

The API and workers share the same broker, so operators control load by scaling worker concurrency. Three load classes exist:

  • Dataset work — scanning and snippet creation on the processing queue. scan_dataset has its own, longer time budget because it can run for hours on very large datasets.
  • Embedding work — chunked across recordings on the embeddings queue; the chunk size is controlled by EMBEDDING_CHORD_CHUNK_SIZE.
  • Training — the PAM active-learning worker has the largest memory allowance of the stack (a 160 GB limit in the Compose file) because it loads embedding matrices and PyTorch models.

Worker memory

The Compose file notes that Celery pool children retain model and audio-decoding memory, so the general worker replaces a child after a configured number of tasks (CELERY_WORKER_MAX_TASKS_PER_CHILD, default 100) to bound memory growth. If the worker still approaches its memory limit, lower the value.

Task time limits

App-wide Celery limits default to 3600s (hard) and 3300s (soft), matching the settings file. The dataset scan task is granted its own much longer budget (default 90000s hard / 86400s soft). Overrides must be passed through the worker environment rather than edited in code.

Database connection pool

Every worker process and uvicorn worker opens its own pool. The stack's worst-case connection count is the sum of processes × (POOL_SIZE + MAX_OVERFLOW) and must stay under the server's PostgreSQL max_connections. The API threadpool limit is meant to match the API pool size (pool size plus overflow) so that synchronous endpoints wait for a thread rather than time out on a connection.

GPU deployments

The stack runs on CPU by default. The GPU file adds NVIDIA device reservations to the API and to both Celery workers; the general worker uses it for embedding inference. Set DEVICE=gpu and select the GPU file: 

DEVICE=gpu
COMPOSE_FILE=docker-compose.yml:docker-compose.gpu.yml

Setting COMPOSE_FILE replaces Docker Compose's default file list, so the override file is not loaded unless you add it, as described under Docker.

PAM_DEFAULT_DEVICE controls which device active-learning training targets (cpu or cuda).

Data mounts

Raw datasets are mounted read-only at /data (HOST_DATA_ROOT). Model checkpoints are stored in /app/models_AL, a bind mount of HOST_MODELS_AL (default ./models_AL) that is writable so retraining can save new checkpoints. Focal-recordings data for the WSSED flow is mounted read-only at /wssed-focal-data.

Migrations

Migrations run automatically on startup in the container. When updating an existing deployment, rebuild containers and verify: 

docker compose down
docker compose build --no-cache
docker compose up -d
docker compose exec api alembic current

Health and monitoring

  • GET /health — liveness probe.
  • GET /api/tasks/status/{task_id} — task progress.
  • Flower at :5555 — queue and task inspection.
Service to service. The API reaches the ontology service at OE_YAPAT_SERVICE_URL (the Compose file points it at host.docker.internal:8002) and the GPU server at WSSED_GPU_SERVER_URL, which Compose does not preset; set it in .env. Label-space grounding also needs outbound access to the GBIF and EBI OLS services.
