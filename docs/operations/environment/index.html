Environment Setup

The backend reads configuration from environment variables, with defaults in app/config.py and a documented example in backend/.env.example. The frontend uses Vite variables.

Mode selection

VariableNotes
DEVICEcpu (default) or gpu; selects the PyTorch build used by the Docker image.
COMPOSE_FILESet to docker-compose.yml:docker-compose.gpu.yml to add GPU runtime.

Connection pools and task limits

The pool variables below are names read by the Compose files, which pass them to each container as DB_POOL_SIZE and DB_MAX_OVERFLOW. The application's own defaults for those two settings are 5 and 5.

VariableDefaultPurpose
API_DB_POOL_SIZE12Per-process pool for the API.
API_DB_MAX_OVERFLOW3API pool overflow.
WORKER_DB_POOL_SIZE2Pool size per Celery worker process.
WORKER_DB_MAX_OVERFLOW2Worker pool overflow.
API_THREADPOOL_LIMIT15Threads for synchronous endpoints; keep ≤ pool size.
CELERY_TASK_TIME_LIMIT3600Hard time limit for general tasks.
CELERY_TASK_SOFT_TIME_LIMIT3300Soft time limit for general tasks.
SCAN_TASK_TIME_LIMIT90000Longer budget for dataset scans.
SCAN_TASK_SOFT_TIME_LIMIT86400Soft budget for dataset scans.
EMBEDDING_CHORD_CHUNK_SIZE25Recordings per embedding chunk task.
CELERY_WORKER_MAX_TASKS_PER_CHILD100Worker memory-recycling threshold.

Defaults vs. deployment. Compose files override some defaults (for example JWT lifetime and broker addresses). Always diff the environment against backend/.env.example and frontend/.env.example when deploying a new stack.
