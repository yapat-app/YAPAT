Docker

The backend ships three Compose files: the base stack in docker-compose.yml, a development override, and a GPU file.

Compose files

File Purpose
docker-compose.ymlBase services: database, Redis, API, workers, beat, Flower.
docker-compose.override.ymlDevelopment override: starts the API with four uvicorn workers and bind-mounts the source directory (.:/app) into the API, workers, beat, and Flower.
docker-compose.gpu.ymlNVIDIA device reservations for the API and both Celery workers.

When COMPOSE_FILE is not set, Docker Compose merges the override automatically. The GPU file must be selected explicitly with COMPOSE_FILE, which replaces that default; to combine all three files, list them (see below).

Services

Service Image / build Host port Notes
db pgvector/pgvector:pg15 5432 PostgreSQL with the pgvector extension; 1 GB shared memory for large similarity queries.
redis redis:7-alpine 6380 Celery broker and result backend; append-only persistence.
api Built from ./Dockerfile 8000 FastAPI; the DEVICE setting selects the CPU or GPU build.
celery-worker Same build — Queues default,embeddings,processing,exports.
celery-worker-pam-al Same build — Queue pam_al; large memory reservations.
celery-beat Same build — Periodic scheduler.
flower Same build 5555 Task monitoring dashboard.

Volumes and mounts

  • postgres_data — database storage.
  • redis_data — Redis persistence.
  • ${HOST_DATA_ROOT}:/data — raw datasets, read-only.
  • ${HOST_MODELS_AL:-./models_AL}:/app/models_AL — model checkpoints, read-write.
  • ${HOST_MODELS_AL:-./models_AL}:/app/assets/models/single_species_models — species model weights, read-only, in the API service.
  • ${HOST_WSSED_FOCAL_DIR}:/wssed-focal-data — focal recordings for the WSSED flow, read-only. The default host path in the Compose file is specific to the maintainers' server, so set it for your environment.

Frontend container

The frontend has its own Dockerfile and docker-compose.yml for serving the built React application. It is never part of the backend stack.

Compose a GPU deployment. Put the file list in .env (or export it) and start the stack normally: 
DEVICE=gpu
COMPOSE_FILE=docker-compose.yml:docker-compose.gpu.yml
# with the development override as well:
# COMPOSE_FILE=docker-compose.yml:docker-compose.override.yml:docker-compose.gpu.yml
docker compose up
See Environment Setup for the variables each service reads.
