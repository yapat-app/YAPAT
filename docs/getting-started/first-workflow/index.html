First Workflow

This walkthrough follows one dataset from registration to exported annotations. It assumes a running backend and frontend, as described in Installation.

1. Create an account and sign in

The sign-up page creates an account with the global role user that belongs to no team. An administrator can instead send a team invitation link from the team list; opening it shows the sign-in form in registration mode, and the new account joins that team. An owner link gives the account the global role team_owner, a member link the role user. Links expire after two days. After registering, sign in with the new account. See Teams for the details.

Signing in opens the Dashboard. It greets you with your role (Administrator, Team owner, or Annotator) and the number of datasets you can access, offers a Start Annotating button that opens the Annotation Hub, and shows a card for each service your role may use:

Card Shown to Opens
Dataset ManagementEveryoneThe Datasets page.
AnnotateEveryoneThe Annotation Hub. The card's text still mentions random feeds and similarity search; the Hub itself offers only active learning.
WSSEDAdministrators, and users with access to a FOCAL_RECORDINGS datasetThe WSSED training page; see Datasets.
Label ManagementEveryoneThe label-space chat.
Feed HistoryEveryoneA page from an older feed design that is not part of the user-study workflow.
Team ManagementAdministrators and team ownersThe team list.
Study LogsAdministratorsThe study-log viewer; see Annotation Hub.
DocumentationEveryoneA user manual built into the frontend (/documentation), separate from these pages.

2. Register a dataset

In the web interface, administrators add datasets from the Datasets page. Adding a dataset means choosing a folder on the mounted data volume and a dataset type, PAM or FOCAL_RECORDINGS. A background task then scans the folder and records each audio file it finds.

3. Generate embeddings

Embeddings are vectors computed for short audio segments. Active learning and the projection view depend on them. On the dataset card, an administrator chooses an embedding model and starts the job. It runs on a Celery worker and, when finished, leaves the dataset with a snippet set that feeds can use.

4. Build a feed

Once the dataset is ready for feeds, open the Annotation Hub, select the dataset, and click Generate Feed. If the dataset has no model checkpoint yet, the dialog asks for a model family name and offers two starts: a cold start that trains a first model from a ground-truth metadata file, or bootstrap mode, which begins with randomly sampled snippets. Once a checkpoint exists, the model ranks the snippets and the dialog sets how many are returned (Top-K).

5. Annotate

Review each snippet's spectrogram and audio, and assign one or more labels. The model's predicted labels are not shown; you choose labels from the quick-label list or find a species through the GBIF search. Your selection is saved to the backend as soon as it changes.

6. Let the model retrain

Each labelled snippet counts as feedback for the dataset's model. When the count reaches the retrain threshold, a retrain job starts automatically, and the feed is ranked again with the updated model.

7. Export

A dataset's annotations can be exported as JSON or CSV. See Import & Export for the filters and the columns.

Study phases. Which views and filters the Annotation Hub shows depends on the study phase. See the Annotation Hub guide and Active Learning.
