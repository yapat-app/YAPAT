What is YAPAT?

YAPAT (Yet Another PAM Annotation Tool) is a web application for labelling audio recorded in passive acoustic monitoring (PAM). A model helps decide which short audio segments an annotator sees next, and the annotator decides which labels are stored.

Purpose

Collecting labelled audio for machine-learning models takes a lot of expert time. The project's stated aim is to reduce that effort by letting a model prioritise which samples are worth an expert's attention, instead of having the expert work through recordings in order.

What YAPAT provides

  • Datasets — folders of audio files on a data volume. YAPAT reads the files in place and never modifies them.
  • Snippets — short, fixed-length segments cut from the recordings. A snippet is the unit that receives labels. With the BirdNET embedding model, which is the model registered by default, a snippet is 3 seconds long.
  • Embeddings — numeric vectors computed for each snippet. They are the input to the active-learning classifier and to the projection of snippets shown in the Annotation Hub.
  • Annotation Hub with active learning — the one place where annotation happens. A model trained on the annotators' labels decides which snippets are shown next and is retrained automatically as labels accumulate. Until a first model exists, bootstrap mode shows randomly chosen snippets.
  • Blind labelling — the model's predicted labels are never shown. Annotators pick one or more labels themselves from a quick-label list or a GBIF species search.
  • Study phases — the Annotation Hub runs in one of five phases (P1 to P5) that decide which views, filters, and sort options are shown. A guided study flow with instructions and a tour, and interaction logging with an admin viewer, can be switched on for study sessions.
  • Label spaces — the lists of concepts that labels are chosen from. They are built through a chat that looks up candidate concepts in GBIF, ENVO, and Wikipedia, and then frozen for a team.
  • Teams — groups that share datasets and label spaces. Access depends on the user's role.
  • WSSED — for focal-recording datasets, a page that trains a sound event detection model on a GPU server and registers it for active learning.

Architecture

YAPAT consists of several components that live in separate repositories. The backend exposes a REST API; long-running work such as dataset scanning, embedding generation, and model training runs in Celery workers.

Component Technology Role
Backend FastAPI, Celery, PostgreSQL (pgvector), Redis REST API, background jobs, and storage for datasets, snippets, embeddings, and annotations.
Frontend React, TypeScript, Vite The annotation interface, including the Annotation Hub, and the pages for datasets, teams, and label spaces.
Ontology service (oe_yapat) MCP tool server Looks up candidate concepts in GBIF, ENVO (through OLS), and Wikipedia for the label-space chat. Optional.
GPU training server (WSSED) FastAPI Trains weakly supervised sound event detection models for FOCAL_RECORDINGS datasets. The WSSED page, shown to administrators and to users with access to such a dataset, starts training and registers the trained model as an active-learning checkpoint. Optional.

How annotation works

Annotation happens in the Annotation Hub. A typical session looks like this:

  1. Choose a dataset and generate a feed; the study phase decides which views and filters are available.
  2. Review each snippet's spectrogram and audio, and assign one or more labels, chosen from the quick-label list or found through a GBIF species search.
  3. After a set number of labelled snippets, the model is retrained and the feed is ranked again.
  4. The labels are saved in the backend database and can be exported as JSON or CSV.
Who decides. The model ranks snippets, but its predicted labels are not shown in the annotation interface. Every stored label is one that an annotator selected.

Getting data out of the API

Every endpoint is served under the /api prefix. An annotation export call looks like this: 

GET /api/datasets/1/annotations/export?format=csv

See the REST API reference for the full list of endpoints.
