Installation

YAPAT is spread over several repositories that the main repository links as Git submodules: the FastAPI backend, the React frontend, the oe_yapat ontology service, and the WSSED GPU training server. This page covers a local setup of the backend and the frontend.

Prerequisites

  • Docker and Docker Compose — for the backend stack.
  • Node.js 20.19 or newer — for the frontend dev server. The frontend uses Vite 7, which requires it; the frontend Dockerfile builds with Node 20.
  • Optional: an NVIDIA GPU and the GPU compose file, which reserves a GPU for the API and the active-learning worker.

Clone the repository

The components are linked as submodules, so clone recursively: 

git clone --recurse-submodules https://github.com/yapat-app/YAPAT.git

If you already cloned without submodules:

git submodule update --init --recursive
A recursive clone is not the user-study version. The main repository records backend commit 108b988 and frontend commit aa92395, and a recursive clone checks out exactly those. They are not the user-study version of YAPAT that these pages describe.

The user-study version is the finalUserStudy branch of the backend and of the frontend. These pages were checked against backend commit 15b3dcd and frontend commit a49d641. After cloning, switch both components: 

git -C backend fetch origin
git -C backend checkout finalUserStudy
git -C frontend fetch origin
git -C frontend checkout finalUserStudy

To reproduce exactly the documented state, check out 15b3dcd in backend and a49d641 in frontend instead. The user-study branches do not specify versions of oe_yapat and WSSED; these pages describe them at the commits the main repository records (2b1d300 and b89375a).

Start the backend

The backend ships a Docker Compose stack that runs the API, database, Redis, Celery workers, and Flower. 

cd backend
cp .env.example .env
# Edit .env — at minimum set HOST_DATA_ROOT to the folder holding your audio
docker compose up

This starts:

  • PostgreSQL (pgvector) on port 5432
  • Redis on port 6380 (mapped to container port 6379)
  • FastAPI on port 8000
  • A general Celery worker (embeddings, processing, exports, default queues)
  • A dedicated PAM Active Learning Celery worker
  • Celery beat for periodic tasks
  • Flower monitoring dashboard on port 5555

Database migrations run automatically on startup. The API is available at http://localhost:8000, and the interaction is served under the /api prefix.

Interactive docs. The generated OpenAPI docs (/docs, /redoc) are served by default. Set ENABLE_DOCS=false in the backend environment to turn them off.

To run detached, stop, or reset the stack:

docker compose up -d      # background
docker compose down       # stop
docker compose down -v    # stop and remove data volumes

Start the frontend

cd frontend
npm install
cp .env.example .env
# Edit .env — review the study-phase settings; set VITE_YAPAT_BACKEND_URL
# if the backend is not at http://localhost:8000
npm run dev

The dev server runs at http://localhost:3000. The frontend calls the backend at VITE_YAPAT_BACKEND_URL, which defaults to http://localhost:8000; set VITE_YAPAT_FRONTEND_URL when invitation links must point at a public address. The example file locks the interface to study phase P1 and turns on the guided study flow; see Environment Setup for these variables.

Optional services

Ontology service (oe_yapat)

The label-space chat sends its prompts to a separate ontology service. The backend reads the service address from OE_YAPAT_SERVICE_URL (default http://localhost:8002; the Compose file sets http://host.docker.internal:8002) and posts to its /api/generate-taxonomy route. Only the label-space chat needs this service; the rest of YAPAT runs without it.

Setup note. The public oe_yapat repository contains the MCP tool server and a command-line client, but no README and no code for the HTTP route the backend calls. Ask the project maintainers how that service is deployed.

WSSED GPU server

Species models for FOCAL_RECORDINGS datasets can be trained on a separate GPU server, WSSED-YAPAT, which is a FastAPI service. The backend reaches it through WSSED_GPU_SERVER_URL (default http://localhost:8003). When the backend runs in Docker, set this to an address the containers can reach; .env.example suggests http://host.docker.internal:8003 for a server on the same host. This flow is optional.

Hosted instance

This documentation links to yapat.ni.dfki.de as the project's hosted instance. The user-study code does not name a hosted address, so which version that instance runs cannot be confirmed from the repositories, and who may use it is decided by its operators. The software itself supports account creation on a sign-up page and through invitation links, described in First Workflow.
