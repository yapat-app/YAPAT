Architecture

YAPAT's interface is a React web app talking to a FastAPI backend. Anything slow, such as scanning folders, computing embeddings, or training models, runs in background workers. This page shows how the parts fit together and where to find them in the code.

Services

Besides the core services, two are optional: the ontology service (oe_yapat) looks up species and environmental terms for the label-space chat; the Weakly Supervised Sound Event Detection (WSSED) server trains a sound event detection model from recordings labelled only with the species they contain, on a machine with a graphics processing unit (GPU). YAPAT can use that model as a dataset's first active-learning model; see WSSED.

ServiceRole
apiThe FastAPI app. Runs database migrations on start.
celery-workerA Celery worker (Celery is a Python task queue): folder scans, snippet creation, and embeddings (queues processing, embeddings, exports, default).
celery-worker-pam-alActive-learning training and retraining (queue pam_al), kept apart so training never blocks other work.
celery-beatSchedules periodic tasks.
db, redisPostgreSQL with pgvector (an extension that stores and searches embedding vectors), and Redis, the message broker that hands tasks to the workers.
flowerFlower, a web dashboard for Celery tasks, on port 5555.

Backend code

PathContains
app/main.pyThe FastAPI app; registers every router under /api.
app/api/One router per area: auth, teams, invitations, datasets, recordings, snippets, embeddings, annotations, pam_active_learning, taxonomy, custom_taxonomy, visualisations, wssed, study_events, tasks, feed, reference_links.
app/models/, app/schemas/SQLAlchemy tables and the Pydantic request and response models.
app/services/The logic behind the routers; active learning lives in app/services/pam_al/.
app/tasks/Celery tasks: processing_tasks, embedding_tasks, pam_al_tasks, wssed_tasks.
app/core/Authentication, permissions, and taxonomy helpers.
active_learning/The classifiers (model_zoo/), the scoring code (samplers.py), and the tunable defaults (config.yaml).
classifiers/Models used by the WSSED workflow.
alembic/Database migrations.
tests/unit/ and integration/ tests (pytest).

Frontend code

PathContains
src/pages/One component per screen; the Annotation Hub is in pages/annotationHub/.
src/components/Shared components; the Hub's feed, projection, and label picker are in components/al/.
src/services/api.tsEvery call to the backend.
src/redux/Application state, one slice per area (datasets, teams, active learning, …).
src/studyPhases/What each of the five phases shows (phases.ts).
src/studyFlow/, src/studyLogging/The guided introductions and the interaction logging.
src/routes/Access guards, for example admin-only pages.
