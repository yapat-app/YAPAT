Pipeline Overview

This page is the technical view of how YAPAT turns raw audio into labelled training data: eight stages, each producing what the next one uses. For the same journey from a user's point of view, see First Workflow.

Stages

Stage 4 is described in Freezing a Label Space; stages 5 to 7 in Active Learning.

Asynchronous execution

Steps 2, 3, and 7 run on Celery workers rather than in the request. The API returns immediately with a task or job identifier, and the client polls for status. Queues are separated so that heavy training does not block interactive work:

  • processing — dataset scanning and snippet creation.
  • embeddings — audio embedding generation.
  • exports — consumed by the general worker; no task is currently routed to it, and annotation export runs in the request.
  • pam_al — active-learning training and retraining.
  • default — general fallback tasks.

Iteration

Steps 5, 6, and 7 form a loop: annotate a batch, let the annotations accumulate, retrain, and generate a new batch ranked by the updated model. Before a model exists, the first feed comes from bootstrap mode, which offers randomly sampled snippets until enough labels exist to train one.
