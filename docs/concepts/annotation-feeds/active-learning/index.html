Active Learning

Active learning means the model asks for help where it needs it most. Instead of going through recordings in order, you label the clips the model is least sure about, so each label teaches it as much as possible.

The loop

Starting without a model

A new dataset has no model yet. The Generate Feed dialog offers two ways to begin:

  • Bootstrap mode — you label randomly chosen clips, and the first model is trained from those labels.
  • Cold start — the first model is trained from existing ground-truth labels. Only administrators and team owners can start it.

A model trained with Weakly Supervised Sound Event Detection (WSSED) can also serve as the first model; see WSSED.

How clips are ranked

The model scores every clip. The feed shows the ones it is most uncertain about, up to the Top-K number you set. Each clip also carries diversity, density, and composite scores, which you can filter and sort by in phases 4 and 5; see Filters and Model Scores.

Why the model's guess is hidden

Labelling is blind: the clip never shows what the model predicts. Each label is your own judgement, not a confirmation of the model's guess, and that independent judgement is what the model learns from.

Models and families

A trained model is saved as a checkpoint in a model family, the name you give in the Generate Feed dialog. For each dataset and family one checkpoint is active, and the Hub uses it; training and retraining create new checkpoints.

For developers.
  • Feed: POST /api/pam-al/inference/get-or-create with suggestion_strategy: "uncertainty" and k.
  • Labels are sent to POST /api/pam-al/feedback with action: "MODIFY".
  • The retrain threshold is RETRAIN_AFTER (10) in active_learning/config.yaml; a dataset's retrain_after_threshold overrides it. Training runs on the pam_al Celery queue.
