Active Learning

Active learning means the model asks for help where it needs it most. Instead of going through recordings in order, you label the snippets the model is least sure about, so each label teaches it as much as possible.

The loop

How the model is built

The model is a classifier trained on the snippets' embeddings. A new dataset has no model, so the Generate Feed dialog (see Generating a feed) asks for a model family name and a way to start:

  • Bootstrap — you label randomly chosen snippets, and the first model is trained from those labels. This is the usual choice.
  • Cold start — the first model is trained immediately from existing ground-truth labels, given as a metadata file and a label config file. Only administrators and team owners can start it.
  • WSSED model — a model trained with Weakly Supervised Sound Event Detection is registered as the first model. See WSSED.

Reference pools

A reference dataset is a labelled dataset used only for training; it is never shown for annotation. An administrator adds it with Add Dataset and links it to a dataset or a team under Reference pools on the dataset card. Its labels are then added to every training run of the linked datasets, including the first. A reference dataset must use the same embedding model as the datasets it is linked to.

Checkpoints

Each training run saves a checkpoint: a numbered version of the model (v0, v1, …) in its model family. For each dataset and family one checkpoint is active, and the Hub ranks the feed with it.

How snippets are ranked

The model scores every snippet. The feed shows the ones it is most uncertain about, up to the Top-K number you set. Each snippet also carries diversity, density, and composite scores, which you can filter and sort by; see Filters and Model Scores.

Why the model's guess is hidden

Labelling is blind: the snippet never shows what the model predicts. Each label is your own judgement, not a confirmation of the model's guess, and that independent judgement is what the model learns from.

For developers.
  • Feed: POST /api/pam-al/inference/get-or-create with suggestion_strategy: "uncertainty" and k.
  • Labels are sent to POST /api/pam-al/feedback with action: "MODIFY".
  • The retrain threshold is RETRAIN_AFTER (10) in active_learning/config.yaml; a dataset's retrain_after_threshold overrides it. Training runs on the pam_al Celery queue.
  • Cold-start metadata and label config paths are resolved relative to the data root. Reference pools are linked with /api/reference-links/ (administrators only).
  • Full details: Active Learning API.
