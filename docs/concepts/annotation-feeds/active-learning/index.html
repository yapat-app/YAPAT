Active Learning

Active learning builds a model from the labels collected so far, scores every remaining snippet, and presents the most useful ones first. It turns annotation into a loop that improves with each confirmed label.

Model checkpoints and families

An active-learning model is stored as a checkpoint belonging to a model family. For a given dataset and family, one checkpoint can be active at a time. Checkpoints are registered and activated through /api/pam-al/checkpoints.

If no checkpoint exists yet, the first run is a cold start: a new model is trained from scratch using ground-truth labels (available to administrators and team owners), an embedding model, and optionally an explicit label configuration and metadata file.

Sampling strategies

Predictions can be ordered by several strategies:

Strategy What it prioritises
uncertaintySnippets the model is least sure about.
diversitySnippets that are spread out in embedding space.
densitySnippets in densely populated regions.
confidenceSnippets the model is most sure about.
randomA uniform sample.
compositeA weighted blend (the default), tuned with composite_wu, composite_wd, and composite_wr.

Each returned snippet carries its uncertainty, diversity, density, and composite scores next to the predicted labels. The interface also uses other per-snippet properties, such as year and day cycle, sound type (Bio, Anthro, or Geo), and the BirdNET and YAMNet labels, to colour or filter the projection.

Getting predictions

POST /api/pam-al/inference/get-or-create
{
  "dataset_id": 1,
  "snippet_set_id": 1,
  "model_family_name": "cold_start_base",
  "sample_suggestion": true,
  "suggestion_strategy": "composite",
  "k": 20
}

If stored predictions exist they are returned; otherwise exactly one inference job is enqueued. Requests are serialised with a database lock so concurrent clients cannot start duplicate jobs. The k parameter, and the option to return only the top-K suggestions, bound how many snippets are proposed.

Feedback loop

For each presented snippet the annotator submits feedback:

  • Accept — the model's suggestion is correct.
  • Reject — it is wrong.
  • Modify — correct or replace the labels.
POST /api/pam-al/feedback
{ "dataset_id": 1, "model_family_name": "cold_start_base",
  "snippet_id": 42, "action": "ACCEPT" }

Feedback is counted per dataset and model family. Once the count reaches the auto-retrain threshold, a retrain job starts automatically. The threshold is PAM_AUTO_RETRAIN_THRESHOLD (default 5), unless the dataset has its own retrain_after_threshold, which an administrator or team owner can set and which takes precedence. Retraining can also be started manually, and its progress is polled through /api/pam-al/retrain/jobs.

In the interface

The Annotation Hub shows active-learning snippets with a ProjectionView beside the prediction feed. The projection is two-dimensional, using PCA, UMAP, t-SNE, or Isomap, and its points can be coloured by properties such as the predicted label, uncertainty, diversity, density, or the composite score.
