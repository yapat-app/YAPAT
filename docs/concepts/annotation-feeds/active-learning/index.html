Active Learning

In the user-study version, annotation in the Annotation Hub is active learning. A model trained on the labels collected so far scores the dataset's snippets, the feed presents them ranked, and the model is retrained as annotators add labels.

Model checkpoints and families

A model is stored as a checkpoint that belongs to a model family, named in the Generate Feed dialog. For a given dataset and family, one checkpoint is active at a time, and the Hub works with that active checkpoint. Training and retraining create new checkpoints.

The first model

When a dataset has no checkpoint yet, the Generate Feed dialog asks whether ground-truth metadata is available:

  • Cold start — with ground-truth metadata, a first model is trained from scratch. The dialog asks for an embedding model, the metadata file, the label-config file, the training device, and whether to run inference after training. Only administrators and team owners can start this training.
  • Bootstrap mode — without ground-truth metadata, the feed starts with randomly chosen snippets. The annotators' labels are stored as feedback, and once the retrain threshold is reached a first model is trained from them.

How the feed is ranked

Once a checkpoint exists, the Hub requests model predictions for the dataset's default snippet set, ranked by the model's uncertainty, and shows the Top-K snippets (1 to 500, set in the Generate Feed dialog). The user-study interface offers no other ranking strategy. Each returned snippet carries its uncertainty, diversity, density, and composite scores. In study phases 4 and 5, the sidebar shows these scores and the model's confidence as histograms, and annotators can filter and sort the feed and the projection by them. 

POST /api/pam-al/inference/get-or-create
{
  "dataset_id": 1,
  "snippet_set_id": 1,
  "model_family_name": "cold_start_base",
  "sample_suggestion": true,
  "suggestion_strategy": "uncertainty",
  "k": 20
}

If predictions for the active checkpoint are already stored they are returned directly; otherwise an inference job is started and the Hub polls for it. When the dataset has no checkpoint, random snippet suggestions are returned immediately.

Feedback loop

Labelling is blind: the model's predicted labels are not shown. For each snippet the annotator selects one or more labels, and the Hub sends them as feedback with the action MODIFY shortly after the selection changes: 

POST /api/pam-al/feedback
{ "dataset_id": 1, "model_family_name": "cold_start_base",
  "snippet_id": 42, "action": "MODIFY", "labels": ["Turdus merula"] }

Feedback is counted per dataset. When the count since the last retrain reaches the threshold, a retrain job starts automatically. The threshold is RETRAIN_AFTER from the backend's active_learning/config.yaml (10), unless the dataset record has a retrain_after_threshold value, which then takes precedence; the user-study interface has no setting for it. The interface has no manual retrain control. When a retrain finishes, the Hub requests new predictions and refreshes the feed.

In the interface

From study phase 2 on, the Annotation Hub shows a ProjectionView beside the feed: a two-dimensional view of the whole dataset, computed with PCA by default or with UMAP or t-SNE, in which labelled snippets are marked. The sidebar filters and the model-score thresholds hide the points that do not match, and in phase 5 a point can be clicked to select its snippet.
