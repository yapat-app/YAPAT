Similarity

The similarity feed uses embeddings to return snippets whose audio lies closest to a reference. The reference can be an existing snippet or a region of an audio file you upload.

Two ways to give a reference

From an existing snippet

GET /api/feed/?method=similarity&dataset_id={dataset_id}&query_snippet_id={snippet_id}&embedding_model_id={model_id}&limit=50

An optional crop_start_sec and crop_end_sec restrict the reference to a sub-region of the query snippet, which is useful when only part of the window contains the sound of interest.

From uploaded audio

POST /api/feed/similarity-search
Content-Type: multipart/form-data

The multipart request carries the audio file plus start_time and end_time selecting the reference region, along with dataset_id, an embedding_model_id, and a result limit. Supported formats are WAV, MP3, FLAC, OGG, M4A, and AAC, up to 100 MB.

How it works

The reference region is embedded with the same model used for the dataset, and the store is queried for the snippet vectors with the smallest cosine distance. Because it relies on the embedding space, the query must use the embedding model that produced the dataset's snippet set.

Like other feed methods, a similarity response is saved as a snapshot so the same result can be revisited from Feed History.

Typical use. Label one clear example of a species, then run a similarity feed from it to quickly find and confirm the rest of its occurrences.
