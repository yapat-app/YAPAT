Grounding

Grounding links a concept described in natural language to an entry in a reference resource, and keeps the identifier and source details that were found.

The workflow

In the label-space chat, an expert describes the concepts they need in ordinary language. For each message the backend asks the ontology service for candidate matches and shows the reply together with the candidates. The expert then adds candidates to the label space, either all at once or one at a time, and can send further messages to refine the search. An added concept can be removed again until the label space is submitted. The papers call this approach grounding-first: alignment with authoritative resources is attempted before a locally defined concept is created.

Reference resources

Resource Used for
GBIF Species and other taxa: name matching, search, details, and occurrence checks.
ENVO through OLS Environmental concepts, looked up in the Environment Ontology through the Ontology Lookup Service.
Wikipedia A fallback that supplies a page reference when no ontology term fits.
Local ontology For a concept with no external match, a tool that builds a small OWL module in Turtle from the expert's description.

How it is implemented

The lookups are carried out by the separate oe_yapat project, whose MCP server exposes tools for GBIF, ENVO/OLS, Wikipedia, and local ontology construction. The YAPAT backend sends each chat prompt to POST {OE_YAPAT_SERVICE_URL}/api/generate-taxonomy, stores the reply in the conversation, and copies the concepts the user selects into the label space, skipping duplicates. The chat endpoints are under /api/taxonomy/chat; for example, POST /api/taxonomy/chat/{conversation_id}/message sends a prompt.

Two lookups do not go through oe_yapat. GET /api/taxonomy/match and GET /api/taxonomy/envo/suggest are answered by the backend itself, which contacts the GBIF match service and the EBI OLS search API directly. Annotating with a species_name uses the same GBIF match, so the backend needs outbound access to those services.

Provenance

Each label-space entry keeps the identifier and the metadata returned by the lookup, such as rank, family, kingdom, and the tool or source that produced it, together with who added it and when. The chat history is stored with the conversation. The backend has no separate grounding-status field, so whether an entry came from GBIF, a fallback, or a locally defined concept has to be read from its identifier and metadata.

Research background. One of the papers defines explicit grounding-status categories and a provenance log for this process. The comparison in Research Context shows which of those ideas the software implements.
