Submitting a Label Space

Submitting finishes a working label space. It becomes a numbered version that waits for the team owner's approval. Once the owner makes it active, its concepts are the label space the team annotates with.

How to submit

In Label Management, click Submit label space under the Current Label Space list. The button is disabled while the list is empty. The interface then confirms "Submitted as" and the version name, and that the label space awaits the team owner's approval.

Approving a version

Team owners, and administrators for every team, see a Label Space Versions list under the current list. Each version can be expanded to preview its concepts; Make active promotes it and the interface confirms "Active label space updated". The active version is marked Active. Until an owner has made a version active, the team has no active label space.

Changing a label space

A submitted version is not edited. To change the label space, build a new list, submit it, and have the owner make the new version active. Earlier versions are kept in the list.

What happens to existing labels

Nothing. Each annotation stores the concept's identifier and name from the moment it was made, so labels stay valid when the label space changes.

For developers. The web interface submits with POST /api/taxonomy/chat/{id}/submit, lists versions with GET /api/teams/{team_id}/label-space/submissions (status submitted, active, archived or all), and reads or sets the active version with GET and PUT /api/teams/{team_id}/active-label-space. The backend version pinned in this repository still provides only the older POST /api/taxonomy/chat/{id}/freeze (see REST API), so use a backend that includes the versioned endpoints. Annotations store taxon_id and resolved_name_snapshot, not a reference to the taxonomy.
