Freezing a Label Space

A label space built in the label-space chat is finalised by freezing it — the Add To label space list button in the interface. Each freeze creates a new custom taxonomy that is immediately usable for annotation, and earlier taxonomies are kept. This page describes that lifecycle as the backend implements it.

From conversation to taxonomy

  1. Start a conversation. A label-space session is opened for a team. If no team is given, the user's first team is used.
  2. Build the concept list. Concepts that the user adds from the chat accumulate in the conversation's label space.
  3. Freeze. Freezing turns the label space into a new custom taxonomy with status active, owned by the conversation's team and attributed to the user who froze it. The web interface names it Label space followed by the date and time. The conversation is marked completed and frozen, and no more concepts can be added to it.
  4. Annotate. The Annotation Hub adds the concepts of the team's most recently frozen label space to the labels annotators can choose from.
No review step. Freezing is the only way the web interface finalises a label space. There is no submission for review and no promotion by a team owner, and a team can hold more than one active custom taxonomy.

Changing a frozen label space

The user-study interface has no screen for renaming, editing, or archiving a frozen label space. To change the concepts, build and freeze a new label space.

What is kept when a label space changes

A change to the label space produces a new taxonomy instead of editing the old one, and earlier taxonomies stay in the database with their status. An annotation stores the taxon ID and a snapshot of the resolved name from the time it was made. The annotation record does not point to a taxonomy.
