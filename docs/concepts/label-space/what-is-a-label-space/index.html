What is a Label Space?

A label space is the set of concepts that annotators choose labels from. In YAPAT its entries carry identifiers and source details, so a label is more than a free-text name.

Labels versus concepts

A plain label list holds only names. An entry in a YAPAT label space is a concept. It stores an identifier such as gbif:2420576, a display name, a scientific name, taxonomic details such as rank, family, and kingdom where the source provides them, the metadata returned by the lookup that found it, and who added it and when. Identifiers from a shared resource make it possible to tell whether two datasets that use the same word, or different words, mean the same thing.

The stored label space is a flat list of such entries. YAPAT does not currently store relations between them.

Taxonomies in YAPAT

YAPAT draws concepts from two kinds of taxonomy:

  • External taxonomies — read-only reference vocabularies such as GBIF for species. They are searched and resolved through the taxonomy API.
  • Custom taxonomies — team- or dataset-specific label spaces built through the label-space chat and stored in YAPAT as versions.

The taxonomy API covers both: GET /api/taxonomy/available lists GBIF and the active custom taxonomies, /suggest and /search find concepts, and /resolve resolves concept IDs.

The active label space

Each team has at most one active label-space version. Only an active version can be used for annotation, and it is what annotators see when they choose labels. A custom taxonomy can have one of four statuses:

Status Meaning
draft Defined in the code but not assigned by the current backend. While a chat session is open, its concepts are held in the conversation, not in a taxonomy.
submitted Created when a member submits a label space. It waits for a team owner to promote it.
active Promoted by a team owner, or created directly by the older freeze endpoint. Usable for annotation.
archived Retired with the archive action. The record stays in the database.

Research background

The papers summarised under Research Context argue that flat, ungrounded label sets limit reuse and interoperability, and that ontology-linked label spaces could carry hierarchy and relations. That is a research argument. The current software keeps identifiers and source details for each concept but does not model hierarchy or relations between them.
