Weakly Supervised Sound Event Detection (WSSED)

Weakly Supervised Sound Event Detection (WSSED) is a way to train a sound event detection model from recordings that are labelled only with the species they contain, not with the exact time of each call. In YAPAT it runs on an optional training server that builds such a model, so active learning can start from a trained model instead of from random clips.

The idea in one paragraph

A sound event detection model finds where in a recording a sound occurs, for example a frog call. Training one normally needs strong labels that mark the exact start and end of every call, which are slow to make. Weakly supervised training only needs weak labels: which species can be heard in a recording, not when. The model splits each recording into short segments, scores every segment, and combines the segment scores into one score for the whole recording (pooling), which it compares with the recording's label. This way of learning from labelled groups of segments is called multiple instance learning.

What it is used for in YAPAT

Many projects already have focal recordings: recordings made to capture one animal or species, typically labelled with that species, for example from a sound library. WSSED turns such a collection into a first sound event detection model. Registered in YAPAT, that model ranks the clips of the dataset straight away, so annotators start in the active-learning loop rather than in bootstrap mode.

The models

ModelHow it learns
BirdNET (default)In two steps: it computes BirdNET embeddings for the recordings, then trains a pooled classifier on them. The embeddings are stored on the server and reused by later jobs.
CDur, TALNetNeural networks for sound event detection that learn directly from mel spectrograms of the audio.

The training panel sets the pooling method (mean, max, or linear), the number of training epochs (50 by default), the learning rate, the detection threshold, the sample rate, and the number of mel bands. For CDur and TALNet it also sets the length of the segments a recording is split into (bag) and the step between them (hop).

How it fits into YAPAT

  1. An administrator, or a user with access to a FOCAL_RECORDINGS dataset, opens the WSSED page from the Dashboard.
  2. Start Training asks the YAPAT backend to create a training job, which it sends to the WSSED server. The page checks the job's progress every five seconds.
  3. When the job has completed, Register for Active Learning copies the trained model into YAPAT's active-learning model store, registers it as a model family, and starts a first ranking of the dataset's clips.
  4. Open Active Learning leads to the Annotation Hub.

The step-by-step version is in the Datasets guide. WSSED is optional: without it, YAPAT starts new datasets in bootstrap mode or from ground-truth labels.

For developers.
  • WSSED is a separate FastAPI service in the WSSED/ submodule (repository WSSED-YAPAT), started from wssed_gpu_server.py on port 8003. Its routes: POST /train, GET /train/{job_id}/status, GET /artifacts, POST /detect (placeholder), and GET /health.
  • It reads datasets below WSSED_DATA_ROOT and keeps job state in WSSED_JOBS_DIR; WSSED_CUDA_VISIBLE_DEVICES picks the graphics processing unit (GPU).
  • The YAPAT backend reaches it at WSSED_GPU_SERVER_URL and exposes the workflow under /api/wssed: training-jobs, training-jobs/{job_id}/dispatch, /status, /register-al, and datasets/{dataset_id}/artifacts. See REST API.
  • Registered weights are copied into PAM_CHECKPOINTS_DIR. The training code (models, pooling) is in WSSED/MainClasses/.
