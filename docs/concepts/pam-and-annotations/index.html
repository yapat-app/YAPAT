PAM and Annotations

YAPAT cuts long recordings into short segments and stores expert labels against those segments. This page describes that data model.

Passive acoustic monitoring

In passive acoustic monitoring, recorders capture audio over long periods. Experts later annotate what can be heard in it, for example species vocalisations and environmental sounds such as wind or rain. Both associated papers use examples of this kind. YAPAT does not fix a particular set of labels; the label space defines which concepts are available.

Datasets and recordings

A dataset is the top-level container. YAPAT supports two dataset types:

  • PAM — the default type, for soundscape recordings.
  • FOCAL_RECORDINGS — recordings used with the WSSED species-model workflow.

A dataset's source_uri points at a folder on the mounted data volume. Registering the dataset schedules a background scan that creates one recording entry per audio file. Recording locations are taken from a location value in the recording's metadata when there is one, and otherwise from the part of the file name before the first underscore.

Snippets

A snippet is a short window of a recording and is the unit of annotation. Snippets are created when embeddings are generated: the embedding model determines the window length and step. For BirdNET, the model registered by default, the window is 3 seconds with no overlap. Snippets belong to a snippet set, which records the window configuration and the model that produced the embeddings.

Each snippet stores its recording, its start and end time, and its duration. The sample rate belongs to the recording. The API serves the snippet's audio as WAV, with the sample rate in a response header, and renders a mel spectrogram as a PNG for the annotation feed.

Annotations

An annotation links a snippet to a label. When creating one, the client supplies either a namespaced taxon_id (for example gbif:2420576, custom:<id>, wiki:65091, or local:vesperis_iridescentis) or a species_name, but not both. A species name is resolved to a taxon ID by the taxonomy service, and the resolved name is stored with the annotation.

  • A snippet can carry several annotations, and they can be created in one batch call.
  • The database allows at most one annotation per snippet and taxon ID, regardless of which user created it.
  • A user can delete their own annotations, and so can any user with access to the snippet's dataset.
  • Annotations created through the API are also mirrored into the active-learning label store as user labels.

Ground truth and user labels

The active-learning label store keeps a source for each label, either user or ground_truth. Only administrators and team owners can edit ground_truth labels, and those labels are what a cold-start model is trained on. When a model is retrained, the collected labels serve as its training data.

Where labels come from. The active label space determines which concepts annotators can choose. See What is a Label Space? for how it is built.
