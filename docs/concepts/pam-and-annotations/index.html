PAM and Annotations

In passive acoustic monitoring (PAM), recorders capture sound in the field for long periods. YAPAT cuts those recordings into short clips so experts can label what they hear: bird songs, frog calls, rain, wind.

The building blocks

TermMeaning
DatasetA folder of recordings. Its type is PAM (soundscapes) or FOCAL_RECORDINGS (for training a Weakly Supervised Sound Event Detection (WSSED) model).
RecordingOne audio file, with metadata such as location, date, and time.
SnippetA short window of a recording, 3 seconds with the default BirdNET model. This is what you label.
AnnotationA label on a snippet. A snippet can have several.

Where labels come from

In the Annotation Hub you choose from one list that combines:

  • the species the dataset's model knows,
  • the dataset's quick labels,
  • your team's frozen label space,
  • species you pinned yourself from the Global Biodiversity Information Facility (GBIF) search.

Every label keeps an identifier from its source, such as gbif:2420576 for a GBIF species, so datasets that use the same label can be compared.

Ground truth and your labels

YAPAT distinguishes ground-truth labels, imported from existing reference data, from the labels annotators give. Ground truth can train a first model (a cold start); without it, the first model is trained from annotators' labels. Only administrators and team owners can edit ground-truth labels.

For developers.
  • A dataset's source_uri is a folder on the data volume; a background scan creates one recording per audio file. Locations are parsed from names like SITE_YYYYMMDD_HHMMSS or imported from CSV.
  • Hub labels are stored as active-learning feedback (source user or ground_truth) and written to the annotation table when they resolve to a taxon ID or species name. Only those appear in exports.
  • Taxon IDs are namespaced: gbif:, custom:, wiki:, local:. One annotation per snippet and taxon ID.
  • Snippet audio is served as WAV; the Hub draws spectrograms in the browser. See Data Models.
